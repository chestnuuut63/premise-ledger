# demo 与评测：逐行导读（答辩用）

> 用法：先自己跑一遍 `python examples/demo.py`，再对照本文看每一段。
> 每个小节末尾的「**你要说的一句话**」是答辩时真正要讲出口的内容，其余是给你自己理解的。

---

## 0. 这 5 分钟你要证明的一件事

不是"我写了一个脚本"，而是：

> **模型算错了不会报错，它错得很体面。我把"每条结论站在哪条前提上"变成机器可查的账，于是"前提一改、哪些结论作废"从猜变成算。**

demo 证明"它真的会算"，评测证明"它比别的做法抓得多"。两者缺一不可。

---

## 1. 样例一：一次完整的生死

### 1.1 登记三前提

```
$ ledger add-premise --text 常住人口 800 万 --symbol population --value 8000000 ...
{
  "ok": true,
  "id": "A2",
  "status": "unverified",
}
```

**看这一行**：`"status": "unverified"`。

登记 ≠ 可信。用户在第 2 轮口述"人口 800 万"，账本收下了，但**明确标记它还没核实**。这一步是整个系统诚实性的起点——大多数 AI 在这一步就直接把它当事实用了。

### 1.2 登记结论 C1

```
$ ledger add-claim --text 日需水量 ≈120 万吨 --inputs percapita,population
{
  "id": "C1",
  "requires": ["A1", "A2"],
  "status": "degraded"
}
```

**看两行**：

- `requires: [A1, A2]` —— 我只告诉它"这个结论用到了 `percapita` 和 `population` 两个量"，它自己查出这两个量分别由 A1、A2 提供，**自动建了两条依赖边**。这叫符号覆盖：不靠模型自觉声明"我依赖谁"，靠"用了谁的量"机械推导。
- `status: degraded` —— 上游两条前提都没核实，所以这个结论一出生就是降级的，不是"正常"。

### 1.3 门禁拦下

```
$ ledger check
{
  "ok": false,
  "issues": [{ "type": "export_gate", "severity": "error",
    "message": "C2 已标记对外输出，但上游 3 条前提未核实..." }],
  "exit_hint": "不可交付：存在 error 级问题"
}
[exit=1]
```

**看 `[exit=1]`**。

这是全篇最重要的一行。它不是"建议你核实一下"，是**退出码 1**——一个机器可读的否决。上层 agent 想让这份报告出门，必须先把这个 1 变成 0。**裁决权在脚本，不在模型。** 模型无权自己说"我看没问题了"。

### 1.4 引用卡片（你答辩要展示的 30 秒）

```
$ ledger cite --id C2
"card": "[C2] 年供水量 ≈4.9 亿吨
         取值：490000000 吨/年
         状态：degraded　引用级别：降级可用
         依赖：A1、A2、A3、C1
         未核实前提：A1（人均综合用水 150 L/(人·天)）、A2（常住人口 800 万）、A3（管网漏损率 10%）
         注意：上游 A1、A2、A3 未核实，引用须注明置信度"
```

**这就是"可引用"具体长什么样。**

不是"我觉得这个数靠谱"，而是一张卡片：编号、取值、状态、依赖谁、哪几条还没核、引用时该怎么标注。

答辩时把这张卡念一遍，比讲十句架构图有用——评委立刻明白"引用"在这里是个**有格式的对象**，不是一句客气话。

### 1.5 第 9 轮：用户改了口径

```
$ ledger retract --id A2 --reason 人口口径改为常住半年以上 --turn 9
{
  "changed": [
    { "id": "C1", "from": "active", "to": "invalidated" },
    { "id": "C2", "from": "active", "to": "invalidated" }
  ],
  "unchanged": [],
  "summary": "撤销 A2：2 条结论状态改变，0 条不受影响"
}
```

**这是整个项目的核心 30 秒。**

用户在第 9 轮说了一句"人口口径改成常住半年以上"。听起来只是改个说法。账本立刻回答：**C1 和 C2 两条结论作废，其余一条没动。**

对比一下普通 agent 会发生什么：它会把新人口数代进去，把 C1 重算一遍，但 **C2 可能忘了改**，或者报告里第 3 轮写的"120 万吨"还留着。这个错误不会报错、不会显得荒谬，它就静静躺在报告第 7 页。

**你要说的一句话**：

> "改了人口口径，它没有只改一个数，它告诉我恰好哪两条结论作废。这件事靠语言能力做不到，得靠图上的遍历。"

### 1.6 事后体检

```
$ ledger check
"issues": [
  { "type": "contamination", "ids": ["C1","A2"], "message": "C1 依赖的前提 A2 已失效..." },
  { "type": "contamination", "ids": ["C2","A2"], "message": "C2 依赖的前提 A2 已失效..." },
  { "type": "export_gate",     "ids": ["C2","A2"], "message": "C2 已标记对外输出，但..." }
]
[exit=1]
```

作废不是"状态改了就算完"，`check` 会把**每一条仍然挂着失效前提的结论**列出来，并附上修复建议。这就是"污染传播"的检测。

## 2. 样例二：同一个撤回，不同结果

结构完全相同，唯一区别：C1 除了 `A1+A2`，还有一组**替代支撑** `A1+A4`（另一份人口数据）。

```
$ ledger retract --id A2 --reason 口述数据不可靠
{
  "changed": [
    { "id": "C1", "from": "active", "to": "degraded" },
    { "id": "C2", "from": "active", "to": "degraded" }
  ]
}
[exit=0]        ← 注意这里

$ ledger check
"exit_hint": "可以交付"
```

**看两处差别**：

| | 样例一 | 样例二 |
|---|---|---|
| C1 变成 | `invalidated`（死了） | `degraded`（降级活着） |
| check 退出码 | 1（不可交付） | **0（可以交付）** |
| 原因 | A2 是必需依赖，断了就断 | A2 断了，但 A4 独立支撑 |

引用卡片也跟着变：

```
已失效前提：A2（常住人口 800 万（口述））
注意：依赖链上 A2 已失效，结论由替代支撑维持，引用须注明降级
```

**这是整个设计里最值钱的一处。**

如果只有"必需依赖"一种边，撤回 A2 就会把所有下游结论一律杀掉——那叫过度反应，工具会变得没人敢用（改一个数全盘重算）。

区分 `requires`（必需）和 `alts`（替代），才让级联**精确**：该死的一个不少，不该死的一个不杀。

**你要说的一句话**：

> "同一句'撤回 A2'，一个死了，一个降级活着。区别不在操作，在于我事先记下了'它还有没有备胎'。这就是精确和全灭的差别。"

## 3. 样例三：六类病一网打尽

故意造一个病态账本，一次 `check` 返回 7 条 issue，覆盖 6 类：

```
"issues": [
  orphan_claim   C1「这个结论没有任何前提支撑」→ 凭空生成
  orphan_claim   C2「用了一个没人提供的量」
  orphan_input   C2 用了 ghost_symbol，账本里没人提供（静默前提）
  phantom_ref    C3 引用了不存在的 A99
  circular       C4 → C5 → C4 循环论证
  contamination  C6 依赖的 A3 已失效
  drift          population 被赋了 2 个不同取值（A1, A2）→ 前提漂移
]
```

末尾打印：

```
捕获到的病种：
  命中  孤儿结论    命中  孤儿输入    命中  幽灵引用
  命中  循环论证    命中  污染传播    命中  前提漂移
```

**这六类不是随便凑的**，它们分别对应人抓不住的六种失效方式：

| 病 | 为什么人抓不住 |
|---|---|
| 孤儿结论 | 读起来很顺，看不出它没依据 |
| 静默前提 | 藏在句子里，没人说"我假设人口不变" |
| 幽灵引用 | 编号看着像真的 |
| 循环论证 | 跨好几轮才成形 |
| 污染传播 | 要跑一遍图才知道 |
| 前提漂移 | 隔了七轮，值悄悄变了 |

**你要说的一句话**：

> "这六类病单看每一条都不荒谬，所以人能读过去。要抓它们，得把对话变成图去查。"

## 4. 评测输出逐行

```
数据集：10 段对话，13 处埋点

## 总表
| 记账方式 | 抓到 / 埋点 | 检出率 | 误报 | 精确率 |
| A 纯文本     |  2 / 13 |  15.4% | 15 |  11.8% |
| B 内联声明   |  8 / 13 |  61.5% |  0 | 100.0% |
| C 完整账本   | 13 / 13 | 100.0% |  0 | 100.0% |
```

**逐行读法**：

- **A 纯文本**：模拟"把对话原文丢给模型，让它自己找矛盾"。抓到 2 处，还误报 15 次——它基本在瞎猜。
- **B 内联声明**：结论后面加 `[依赖 A1,A2]`。抓到 8 处，误报 0。**加了编号就大幅提升**，说明"引用"这个格式本身有巨大价值。
- **C 完整账本**：13/13，误报 0。补上了 B 缺的东西。

**关键不是 100%，是 B 到 C 的这一步。** 请看下一张表。

```
## 分项检出率
| 病种     | 埋点 | A 纯文本 | B 内联声明 | C 完整账本 |
| 孤儿结论 | 2 | 2/2 | 2/2 | 2/2 |
| 孤儿输入 | 2 | 0/2 | 0/2 | 2/2 |
| 幽灵引用 | 1 | 0/1 | 1/1 | 1/1 |
| 循环论证 | 2 | 0/2 | 2/2 | 2/2 |
| 污染传播 | 3 | 0/3 | 3/3 | 3/3 |
| 前提漂移 | 3 | 0/3 | 0/3 | 3/3 |
| 交付门禁 | 1 | 0/1 | 0/1 | 1/1 |
```

**这一张是整份作业最有说服力的一张表。**

B 组漏掉的恰好只有三类，而且**全是 0**：

- **孤儿输入**（0/2）：需要一个"符号表"——记下每个量由谁提供。散文里没有这个表。
- **前提漂移**（0/3）：需要"版本历史"——同一个量被赋了两次值要能比对。散文里没有版本。
- **交付门禁**（0/1）：需要"对外标记"——哪条结论是准备发出去的。散文里没有这个概念。

**所以结论不是"B 组模型不够聪明"，而是"散文这种表示装不下这三样东西"。**

这就是海报主标题：**不是模型不行，是散文装不下依赖。**

```
## B 组漏掉了什么
- 前提漂移：漏 3 处
- 孤儿输入：漏 2 处
- 交付门禁：漏 1 处
```

脚本自己把"我漏在哪"打印出来，而不是只报一个总分。这是可诊断性。

```
## 阴性对照（把 13 处埋点全部治好后再检测）
- 10 段健康账本，误报 0 处 —— 检测器不会在没病时乱报警。
```

**这一行是防守用的，必须主动讲。**

评委一定会问："C 组 100%，是不是你自己出题自己考？"

答：所以我把 13 处病**全部治好**（统一漂移值、补上孤儿依赖、断环、前提标回已核验），得到 10 段健康账本再跑一遍——**误报 0**。

这说明检测器不是"有输入就报警"混分，它在没病的时候确实沉默。

```
一句话结论：同样 10 段对话，检出率从 15.4%（纯文本）→ 61.5%（内联声明）→ 100%（完整账本）。
```

## 5. 三个必被追问的问题

| 追问 | 怎么答 |
|---|---|
| **"让模型自己列一下假设不就行了？"** | 列假设是一次性动作，账本是持续约束。改一个数时它要能算出"恰好哪几条作废"，这是图上的运算，不是语言能力。样例一和样例二就是同一个操作、两种结果的证明。 |
| **"C 组 100%，是不是自己出题自己考？"** | 是，所以我做了阴性对照：13 处全治好，误报 0。而且 C 组衡量的是**检测器**能力，不是标注质量——标注质量靠人工基线那张表。 |
| **"这东西有什么用？"** | 长对话里模型自相矛盾是常态，人抓不住，因为错误不荒谬、不报错、读起来很顺。它把这个变成可查的账。任何多轮建模、论文推导、数据分析都用得上。 |

## 6. 五分钟逐字稿

**第 1 分钟 · 问题**

> AI 算错了不会报错，它错得很体面。第 3 轮说人口 800 万，第 9 轮改成 900 万，结论还挂在 800 万上，报告读起来毫无破绽。人抓不住，因为错误不荒谬。真正的 agent 协作问题不是算不出，是算完之后算错了查不出来。

**第 2 分钟 · 做法**

> 我给 agent 配一个账本。每条前提、每条结论都有编号；每条结论注明它站在哪几条前提上。前提一撤，账本算出恰好哪几条结论作废。它不产生答案，它管答案之间的关系。

**第 3 分钟 · 演示（跑 demo）**

> 这里撤回 A2，它返回两条结论作废，其余不动。同一操作在下一个例子里，因为结论有备用数据源，就降级存活、仍然可以交付。这就是精确和全灭的差别。

**第 4 分钟 · 评测**

> 同一批 10 段对话、13 处埋点，只改记账方式：纯文本 15%，加内联依赖声明 62%，完整账本 100%。关键是中间那一步——漏掉的恰好是孤儿输入、前提漂移、交付门禁三类，全是因为散文里没有符号表、没有版本、没有对外标记。不是模型不行，是表示方式装不下。

**第 5 分钟 · 诚实边界**

> 局限有两个：一，标注是我做的，所以加了阴性对照，13 处全治好误报 0；二，它只管账，不管算得对不对——数字本身对不对得靠别的工具验。它保证的是：如果前提变了，你不会拿着过期结论去做决策。

## 7. 加餐：3 分钟现场互动

如果时间允许，把第 3 分钟换成这个，效果比单方面演示强得多——**让评委自己当一次审稿人**。

**准备**（提前发或投影）

- `demo_live/audience_sheet.md`：29 句对话，埋了 8 处，每人一份
- 白板 + 马克笔，用来记票数

**流程**

| 步骤 | 时间 | 你说什么 |
|---|---|---|
| 发题 | 30 秒 | "这段对话在算一个充电宝项目能不能回本。里面有 8 处站不住，3 分钟，把你认为有问题的**句号**写在纸上。" |
| 做题 | 3 分钟 | 不说话。让沉默生效。 |
| 收票 | 1 分钟 | "S21 有几票？S23 呢？"把票数写白板。**先别说对错。** |
| 揭晓 | 1 分钟 | 跑 `python demo_live/run_live.py`，逐行念。 |
| 收尾 | 30 秒 | "刚才有谁一个人找到 6 处以上？"（通常一两个人举手）"全找到 8 处的？"（基本没有人） |

**跑出来的结果**

```
1  S19   幽灵引用      ✓    C11
2  S21   污染传播      ✓    5 条结论：C8 C9 C10 C14 C16
3  S23   前提漂移      ✓    A1/A10 同符号不同值
4  S24   前提漂移      ✓    A6/A11 同符号不同值
5  S25   循环论证      ✓    C12 C13
6  S26   孤儿输入      ✓    C14
7  S27   孤儿结论      ✓    C15
8  S29   交付门禁      ✓    C16 上游 8 条前提
8 处埋伏全部命中：8/8
```

**收尾那句话**（这是全场最重要的一句）

> "这段对话没有任何一处算错。80 台、43.2 万、25.9 万、17.7 万，每一步都对。**但整份材料不能用。**
> 因为其中 5 条结论建立在一个已经被否掉的单价上，而它们仍然标着'可以外发'。
> 我刚才做的，就是让机器替你们盯住这件事。"

**预判两个现场追问**

| 追问 | 答 |
|---|---|
| "S23 只是改个数字，也算错？" | 改数字本身不错，错在**没重算**。80 台是按 2.4 万人算的，改成 2.1 万之后，80 台这个前提就悬空了。账本报的是"漂移"，意思是：先确认哪个值权威，再谈重算。 |
| "S27'建议立项'也算错？太严了吧？" | 建议本身可以有，但建议必须挂在依据上。账本不禁止你建议，它要求你写明"依据 C10 回本期 2.4 年"——而 C10 恰好已经失效了。这正是它该拦的地方。 |
