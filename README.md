# premise-ledger · 给 AI 的推理记账

> 模型不会记账，所以它错得很体面。

多轮建模对话里最危险的错误不是算错，而是**前提被悄悄换掉，结论还挂着**。第 9 轮你说"人口其实是 900 万"，第 3 轮的"日需水 120 万吨"不会自动失效——它只是静静留在报告里，读起来毫无破绽。

`premise-ledger` 是一张随对话生长的**前提-结论依赖图**：每条结论都注明它站在哪几条前提上；前提一撤，脚本自动算出**恰好哪几条结论作废**，不多也不少。

## 它解决什么

| 病 | 表现 | 人为什么抓不住 |
|---|---|---|
| 孤儿结论 | 结论无前提，凭空生成 | 读起来很顺 |
| 孤儿输入 | 用了一个没人提供的量 | 它就藏在句子里 |
| 幽灵引用 | 引用不存在的 A7 | 编号看着像真的 |
| 循环论证 | A1 靠 C2，C2 靠 A1 | 跨轮才成形 |
| 污染传播 | 前提已被否，结论还挂着 | 得跑一遍图才知道 |
| 前提漂移 | 同一量出现两个取值 | 隔了七轮 |

外加一道**交付门禁**：结论要对外输出时，上游有未核实前提就拦下。

## 核心设计：两种依赖

这是本项目和"给模型加提示词"的分水岭：

- `requires`（必需）：缺了它，结论必死
- `alts`（替代支撑组）：原路径断了，若这组全活，结论**降级存活**而非作废

有了这层区分，级联才是精确的。实测（`examples/demo.py`）：

| 场景 | 撤回 A2 后 |
|---|---|
| 无替代支撑 | C1、C2 全部 `invalidated`，2 条状态改变 |
| 有替代支撑 A1+A4 | C1、C2 转 `degraded`，仍可用但须注明降级 |

如果只有一种边，撤回一条前提就是全图崩塌，账本立刻沦为噪音——这是设计里最关键的一处取舍。

## 快速开始

```bash
python scripts/ledger.py new --task "某市供水测算"

# 登记三条前提
python scripts/ledger.py add-premise --text "人均用水 150 L/(人·天)" --symbol percapita \
    --value 150 --unit "L/(人·天)" --conf 0.9 --src spec --turn 1
python scripts/ledger.py add-premise --text "常住人口 800 万" --symbol population \
    --value 8000000 --unit 人 --conf 0.4 --src 用户口述 --turn 2
python scripts/ledger.py add-premise --text "漏损率 10%" --symbol loss \
    --value 0.1 --unit - --conf 0.6 --src estimate --turn 2

# 结论：inputs 会自动解析成依赖
python scripts/ledger.py add-claim --text "日需水 ≈120 万吨" --symbol demand \
    --value 1200000 --unit "吨/天" --inputs percapita,population --turn 3

# 体检 + 引用卡片
python scripts/ledger.py check
python scripts/ledger.py cite --id C1

# 用户改口：撤回前提，看级联
python scripts/ledger.py retract --id A2 --reason "人口口径变更" --turn 9
```

一键跑完三段样例：

```bash
python examples/demo.py
```

## 现场互动：3 分钟，让大家当一次审稿人

`demo_live/` 是一段 29 句、跨 8 轮的完整测算对话（校园共享充电宝投放），埋了 **8 处**问题。

```bash
python demo_live/run_live.py --emit   # 生成观众答题卡与答案键
python demo_live/run_live.py          # 现场跑：逐句记账 → 撤回级联 → check 揭晓
```

流程：发答题卡 → 给 3 分钟 → 收句号 → 跑脚本逐行揭晓。

实测输出：

```
--- 揭晓：8 处埋伏，账本抓到这些 ---
#  句号    病种        检出   牵动的节点
1  S19   幽灵引用      ✓    C11
2  S21   污染传播      ✓    5 条结论：C8 C9 C10 C14 C16
3  S23   前提漂移      ✓    A1/A10 同符号不同值
4  S24   前提漂移      ✓    A6/A11 同符号不同值
5  S25   循环论证      ✓    C12 C13
6  S26   孤儿输入      ✓    C14
7  S27   孤儿结论      ✓    C15
8  S29   交付门禁      ✓    C16 上游 8 条前提
8 处埋伏全部命中：8/8。check 共报 12 条
```

为什么 8 处变 12 条：观众按「句」计，账本按「结论」计——第 21 句刚否掉运维单价，下游 5 条结论一起作废。

## 评测

不做「比模型谁聪明」，做**表示消融**：同一批对话，只改变"怎么记账"，看能抓出多少问题。三组全部是确定性脚本，任何人跑都是同样的数字。

| 组 | 记账方式 | 能拿到什么 |
|---|---|---|
| A | 纯文本 | 只认得出有哪些结论，拿不到任何依赖边 |
| B | 内联声明 `C3 = 值 [依赖 A1,A2]` | 有依赖边，但没有符号表、没有版本、没有交付门禁 |
| C | 完整账本（本项目） | 全部字段 |

复现：

```bash
python evaluate.py
```

| 记账方式 | 抓到 / 埋点 | 检出率 | 误报 | 精确率 |
|---|---|---|---|---|
| A 纯文本 | 2 / 13 | 15.4% | 15 | 11.8% |
| B 内联声明 | 8 / 13 | 61.5% | 0 | 100.0% |
| **C 完整账本** | **13 / 13** | **100.0%** | **0** | **100.0%** |
| H 人工（无工具） | 7 / 13 | 53.8% | 4 | 63.6% |

**H 组：人工基线。** 一个人不通读代码、不用任何工具，只按平时审稿的方式读这 10 段对话（共 322 秒，平均 32 秒/段）。结果：**抓到 7/13（53.8%），误报 4 处**。

这一行比 C 组的 100% 更有信息量：

- **人比纯文本 AI 强**（53.8% vs 15.4%），说明人在读"意思"时确实能察觉到不对劲；
- **人明显不如内联声明**（53.8% vs 61.5%），而内联声明只是多写了一行 `[依赖 A1,A2]`；
- **人有 4 处误报**，精确率只有 63.6%——"觉得哪里不对"和"指出是哪一类病"是两种能力。
- 最能说明问题的是 D01：7 轮、最长的一段，花了 **130 秒（占总时长 40%）**，命中 **0 处**。剩下的 9 段平均只用 21 秒。**对话越长，人越抓不住**——这正是账本要解决的场景。

分项检出率说明了差异到底来自哪：

| 病种 | 埋点数 | A | B | C |
|---|---|---|---|---|
| 孤儿结论 | 2 | 2/2 | 2/2 | 2/2 |
| 孤儿输入 | 2 | 0/2 | 0/2 | 2/2 |
| 幽灵引用 | 1 | 0/1 | 1/1 | 1/1 |
| 循环论证 | 2 | 0/2 | 2/2 | 2/2 |
| 污染传播 | 3 | 0/3 | 3/3 | 3/3 |
| 前提漂移 | 2 | 0/2 | 0/2 | 2/2 |
| 交付门禁 | 1 | 0/1 | 0/1 | 1/1 |

**B 组漏的三类，恰好都依赖"账本独有的字段"**：符号表（孤儿输入）、版本历史（漂移）、对外标记（门禁）。这不是模型能力差异，是**表示能力的差异**——散文里根本没有这些概念，再强的模型也查不出来。

**阴性对照**：把 13 处埋点逐项"治好"，得到 10 段健康账本，再跑检测 —— 误报 0 处。说明检测器不会在没病时乱报警。

**诚实的边界**：C 组 100% 是在"标注正确"的前提下取得的，它衡量的是**检测器**，不是标注质量。所以补了两道防守：

1. **人工基线**（上表 H 行）：同一个人、同一批对话、不用工具，只抓到 53.8% 且误报 4 处。说明这 13 处病不是"显然可见"的，标注门槛本身是真实存在的。
2. **人工基线自身的局限**：单人、单次、平均 32 秒/段，属于快速通读而非深思熟虑。若做多人重复盲评，人工检出率大概率会高于 50%——这是本报告需要明说的偏差方向。

复现命令：

```bash
python tools/make_sheet.py                            # 生成测评表与答案键
python evaluate.py --human results/human_filled.csv   # 合并人工结果
```

## 设计取舍（答辩要点）

1. **粒度**：只收能被单句否定的陈述，分参数取值 / 结构假设 / 范围假设三类。太细则模型维护不动，太粗则"模型是线性的"吞掉一切。
2. **依赖边谁来定**：不靠模型自觉。结论必须声明 `--inputs`，脚本按 `symbol` 自动解析；解析不到就是孤儿输入，当场报警。
3. **状态不持久化**：结论状态每次实时推导，因此不可能出现"缓存状态过期"这种病。
4. **打断时机**：不是每步都要求登记，只在三个时刻强制——结论要对外、数值被下游使用、前提被改写。
5. **裁决权**：只有 `check` 的退出码能宣布"可交付"，agent 无权自封。

## 局限

- **它只管已登记的东西**：模型没意识到自己是假设的那条，账本抓不到，只能靠 `--inputs` 的孤儿检查逼近。这是本方案最大的漏口，需在论文中明确。
- 不判断前提本身在现实世界是否成立，只判断它在账本里是否被核实过。
- 不做数值计算，也不验证公式推导是否数学正确。
